# 출력 로케일 (i18n)

airlock의 사람용 출력을 한국어와 영문으로 전환하는 기구다. 기본은 한국어이며, 어떤 환경 신호도 없으면 기존 동작이 그대로 유지된다.

## 1. 무엇이 로케일을 따르는가

로케일은 **표시 계층만** 바꾼다.

로케일을 따르는 것.

- CLI 도움말(`--help`), 배너와 한계(limit) 목록, 세션 요약, 경고와 오류 산문
- `/dev/tty` 승인 프롬프트와 응답 표기
- `airlock audit verify` · `show` · `report` · `ack` 의 사람용 출력
- `airlock setup` 마법사의 모든 질문과 산출물(정책 파일)의 주석
- 감사 보고의 이상 `detail` 산문과 `--json` 안의 산문 필드

로케일과 무관하게 고정인 것.

- 기계 판독 필드 전부. JSON 키, 스키마 이름(`airlock.audit-report.v1` 등), `kind` · `status` · `verdict` 의 `as_str` 값, 규칙 id, 프로토콜 태그, 인코딩 도메인 상수
- **정책 다이제스트.** 정책의 의미는 표시 언어와 무관하다. 한국어판과 영문판 프리셋은 주석만 다르고 다이제스트가 같으며, 테스트가 이 동일성을 강제한다
- 커널에 넘어가는 프로파일의 의미 부분. SBPL 주석(`;;`)만 로케일을 따른다

감사 로그 안의 산문 필드(승인 note, 거부 사유 등)는 **기록 시점의 로케일**로 남는다. 로그는 append-only이므로 뒤에 로케일을 바꿔도 이미 남은 산문은 바뀌지 않는다.

## 2. 로케일 결정 순서

1. `AIRLOCK_LANG` 환경 변수 (`ko` 또는 `en`)
2. 구성 파일 `~/.config/airlock/config.toml` 의 `locale` 키. `XDG_CONFIG_HOME` 이 절대 경로면 그 아래를 본다
3. `LC_ALL` -> `LC_MESSAGES` -> `LANG` 의 언어 접두 감지. `en_US.UTF-8` 은 `en`, `ko_KR` 은 `ko`
4. 기본값 한국어. `C`/`POSIX` 를 포함해 모르는 값은 다음 순서로 조용히 내려간다

읽기 실패도 조용히 다음 순서로 내려간다. 로케일은 표시 전용이라 실패가 보안 판정을 바꾸지 않기 때문이다. 값을 추측하지는 않는다. 따옴표 없는 값이나 테이블(`[section]`) 안의 `locale` 은 최상위 키가 아니므로 읽지 않고 다음 순서로 내려간다.

저장은 `locale` 줄 하나만 바꾸거나 넣고 나머지 줄은 한 바이트도 건드리지 않는다. 전체를 파싱해 다시 쓰면 사람이 적어 둔 주석과 배치가 바뀌고, 파서가 이해하지 못하는 파일을 통째로 잃는다. 최상위 `locale` 줄이 없으면 첫 테이블 머리 앞에 넣는다. 끝에 붙이면 그 키가 마지막 테이블 안으로 들어가 최상위 키가 아니게 되기 때문이다.

```toml
# ~/.config/airlock/config.toml
locale = "en"
```

## 3. 왜 정책 파일이 아닌가

정책 파일(`airlock.toml`)에 로케일을 두면 표시 언어를 바꿀 때마다 정책 다이제스트가 달라져 감사 로그에 소음이 생긴다. 로케일은 어떤 판정도 바꾸지 않으므로 정책 밖(별도 구성 파일)에 둔다.

## 4. 설정 경로

- `airlock setup` 의 **첫 질문**이 언어 선택이다. 답하는 즉시 나머지 질문이 그 언어로 나가고, 선택이 구성 파일에 저장된다. 저장 실패는 경고로만 남고 마법사는 계속된다
- 이미 구성 파일이 있으면 그 값이 초기 선택으로 뜬다
- 일회성 전환은 `AIRLOCK_LANG=en airlock run ...` 처럼 환경 변수로 한다

## 5. 프리셋 영문판

`examples/policy/en/*.toml` 이 영문 프리셋의 원본이고 `crates/airlock-setup/presets/en/` 에 사본을 둔다. 한국어판과의 관계는 다음 테스트가 강제한다.

- `presets_stay_in_sync_with_examples` 두 벌(사본과 원본)의 바이트 동일성
- `en_presets_only_differ_in_comments` 한국어판과 영문판의 **정책 다이제스트 동일성.** 주석 번역이 규칙을 건드리면 실패한다

## 6. 리포트 다이제스트와 로케일

`airlock audit report` 의 본문 다이제스트는 이상 `detail` 산문을 포함하므로 **생성 로케일에 묶인다.** `report` 로 본 다이제스트와 `ack` 가 찍는 다이제스트가 일치하려면 두 명령을 같은 로케일에서 돌려야 한다. 같은 구성 파일을 읽는 한 자연히 일치하며, `--json` 의 `locale` 필드가 어느 로케일로 생성되었는지를 남긴다. 자세한 것은 `docs/limitations.md` 7.18.

## 7. 개발 규약

- 크레이트 `airlock-i18n` 이 `Locale` 과 전역 상태와 `tr!` 매크로를 제공한다. `main` 이 시작하자마자 `airlock_i18n::init()` 을 부른다
- **`airlock-i18n` 에는 의존이 하나도 없다.** 이 크레이트는 브로커와 정책 엔진의 의존성 트리에 들어가므로, 여기에 파서나 UI 의존성을 넣으면 `docs/setup-wizard.md` 가 정한 TCB 경계가 넓어진다. 구성 파일에서 읽는 것이 짧은 문자열 하나뿐이라 최소 스캐너로 충분하며, 그래서 TOML 파서를 쓰지 않는다
- 모든 사용자 대면 문자열은 `tr!("한국어", "english")` 쌍으로 적는다. 한 쪽만 있는 문자열을 남기지 않는다
- `tr!` 은 포맷하지 않는다. 치환이 필요하면 `tr!(format!("... {x}"), format!("... {x}"))` 로 각 갈래를 `format!` 으로 감싼다. 감싸지 않은 `{}` 자리표시자를 `tr!` 리터럴에 남기면 그대로 출력되는 버그다
- 한국어 원문은 정본이다. 번역을 고치더라도 한국어 쪽을 함께 검토 없이 바꾸지 않는다. 테스트는 기본 로케일(ko)에서 돌며 한국어 문자열을 그대로 단정한다
- 단위 테스트에서 전역 로케일을 바꾸지 않는다. 테스트는 병렬로 돌므로 전역을 바꾸면 다른 테스트가 오염된다. 영문 경로는 `Locale` 을 인자로 받는 함수로 검증한다
