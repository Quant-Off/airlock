# 대한민국 전자금융감독규정 준수

2026년 4월 20일부터 금융보안원 평가를 통과한 SaaS에 한해 내부망 이용을 허용하는 전자금융감독규정 시행세칙 개정안이 정식 시행되었습니다. 이 섹션은 보안 수준 저하를 막기 위한 시행세칙 별표 7의 각 항목에 대해 `airlock`이 실제로 무엇을 강제하고 무엇을 강제하지 못하는지 적은 것입니다.

**준수 표시(체크박스)는 두지 않습니다.** 왜냐하면 airlock은 별표 7의 어떤 항목도 단독으로 준수할 수 없으며, 그것은 남은 구현 과제가 아니라 아래에 적은 구조적 이유 때문입니다. 체크박스는 "언젠가 채워질 수 있다"는 뜻을 담기 때문에 제거했습니다.

## 준수 표시를 두지 않는 이유

### 1. 조항이 요구하는 것은 제품이 아니라 대책이다

별표 7의 항목은 대부분 "~ 대책 수립"이라는 형식입니다. 대책은 정책 문서·책임자·절차·기록·주기적 점검으로 이루어지고, 그것을 수립하는 주체는 금융회사입니다. 소프트웨어는 대책의 집행 수단이 될 수 있을 뿐 대책 그 자체가 될 수 없습니다. 곧 airlock뿐 아니라 어떤 단일 제품도 이 항목들을 단독으로 충족한다고 말할 수 없습니다.

### 2. 신뢰 앵커가 조항과 반대 방향이다

이것이 가장 중요합니다. 별표 7은 **조직이 사용자 단말에 통제를 강제하는** 구도를 전제합니다. 반면 airlock의 신뢰 경계는 "브로커 vs. 에이전트"이고 **사용자는 경계 안쪽**입니다. 구체적으로,

- 정책 파일은 호출자 uid가 소유하고 group·other 쓰기가 없으면 그대로 신뢰됩니다(`airlock-policy/src/path.rs:51`). 서명도 중앙 배포도 요구하지 않기 때문에 사용자가 언제든 다시 쓸 수 있습니다.
- 감사 로그 위치는 `AIRLOCK_AUDIT_DIR`로 사용자가 옮길 수 있습니다(`airlock/src/paths.rs:57`).
- 무엇보다 명령 앞에 `airlock run --`을 붙이지 않으면 아무 통제도 걸리지 않습니다.

**통제 대상이 스스로 해제할 수 있는 통제는 그 조항이 요구하는 통제가 아닙니다.** 이건 메우면 되는 격차가 아닌 설계 차원의 선택입니다. airlock의 신념인 "신뢰를 버리고 격리를 택하라"에서 버리는 신뢰는 에이전트에 대한 신뢰이지 사용자에 대한 신뢰가 아닙니다. airlock은 조직이 사용자를 감시하는 도구가 아니라 사용자가 에이전트를 가두는 도구입니다. 곧 airlock은 별표 7이 요구하는 통제의 **집행 지점**은 될 수 있으나, 사용자가 그것을 끄지 못하게 하는 **관리 주체**는 아닙니다.

### 3. 관측 영역이 좁다

airlock이 보는 사건은 파일 열기·프로세스 실행·아웃바운드 연결·사람 승인 넷뿐입니다. 메일 본문과 첨부, 디스크 전체의 저장 데이터, 계정의 권한 구성, 원격접속 세션 자체는 이 영역에 아예 나타나지 않습니다. 취소선 항목은 이 이유만으로 범위 밖입니다.

### 무엇이 바뀌어야 하는가

1번과 3번은 다른 제품·절차와 함께 쓰면 메울 수 있습니다. 남는 건 2번이고, 이를 위해선 최소한 다음 세 개의 기술적 사항이 필요합니다.

- 중앙에서 서명된 정책 배포와 실행 시점의 서명 검증. 자리는 감사 제네시스의 `policy_signer` 필드로 예약만 되어 있고 값은 항상 `None`입니다.
- 사용자가 airlock을 비껴가 에이전트를 띄우지 못하게 하는 실행 경로 강제. 이건 단말 관리 제품의 일이며 airlock 밖입니다.
- 감사 로그의 조직 측 원격 수집. 지금은 앵커 체인을 다른 볼륨에 두는 것까지가 전부입니다.

셋을 다 갖춰도 항목별 격차는 따로 남으며, 판정 기준 아래의 표에서 "근거와 남은 격차" 행이 이를 나타냅니다.

| 15 | 내부 업무용 시스템 접근 통제                           | 미준수  | egress allowlist가 목적지를 좁히지만 정책 파일의 신뢰 앵커가 사용자입니다. 대상이 스스로 완화할 수 있는 통제는 조직 통제가 아닙니다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 16 | 모든 작업 내역 기록 + 매일 이상여부 점검 + 책임자 확인 | 부분    | **점검과 확인은 실물이 생겼습니다.** `airlock audit report`가 cron에 걸리고 이상이 있으면 비영으로 끝나며, **판단 불가를 통과로 보고하지 않습니다**(앵커 없음도 이상으로 셉니다). `airlock audit ack`가 확인자 uid·euid·tty와 리포트 다이제스트를 `reviews.jsonl`에 해시체인으로 봉인합니다. 세션 상위 앵커 체인이 세션 통째 삭제와 체인 재계산을 탐지하되 **앵커를 다른 볼륨으로 분리했을 때만** 실효가 있습니다. **"모든 작업 내역"이 가장 크게 열려 있습니다.** macOS는 중계 기구가 없어 자식 프로세스의 파일 열기와 exec을 기록하지 못하고(아웃바운드만은 `--egress-proxy` 세션에 한해 기록되며, 그때는 seatbelt가 아웃바운드를 프록시 주소로만 허용해 자식이 프록시를 비껴가지 못합니다), Linux도 `--mediate full`이 아니면 파일 열기가 빠지며 io_uring은 중계를 비껴갑니다. 커널이 거부한 접근은 양 플랫폼 모두 로그에 남지 않습니다. 곧 점검 절차는 갖췄으나 점검 대상이 "모든 작업 내역"이 아닙니다. 확인 기록도 계정을 증명할 뿐 사람을 증명하지 못합니다 |

준수로 판정된 항목은 없고, 위의 2번 때문에 airlock 단독으로는 앞으로도 생기지 않습니다. 부분 5건(2·3·7·12·16), 미준수 8건(1·6·8·10·11·13·14·15), 범위 밖 3건(4·5·9)입니다. **부분은 조항의 일부 국면이 실제로 커널에서 강제된다는 뜻이지 항목을 준수한다는 뜻이 아닙니다.** 남은 격차는 전부 `docs/limitations.md`에 코드 위치와 함께 적혀 있습니다.

## 확인 방법

판정을 그대로 믿지 말고 직접 확인할 수 있습니다.

```bash
# 7번: 허용 목록 밖 프로그램이 커널에서 거부되는지
$ airlock run --policy examples/policy/strict.toml -- \
    sh -c 'curl --version || echo BLOCKED'

# 12번: 정책이 호스트를 열어도 평문이 막히는지
$ airlock run --egress-proxy -- curl http://example.com/

# 16번: 체인을 변조하면 점검이 비영으로 끝나는지
$ airlock run --anchor-dir /Volumes/audit -- <명령>
$ airlock audit report --anchor-dir /Volumes/audit --json
$ echo $?
```
